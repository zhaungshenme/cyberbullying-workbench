# 生产架构与多模型工作流

目标是把网络语言材料组织为可核验、可追踪、可复核的事件观察，同时兼顾吞吐、误报与可解释性。模型参数规模不能替代数据质量和独立评测。

## 当前链路

浏览器 → Next.js BFF → FastAPI → Dify 引用提交 → FastAPI 队列 worker → 受限网关 → 模型 → 服务端证据校验 → 用户权限下的结果与复核。

当前 Dify DSL 包含输入、材料健康检查、分支、幂等提交与返回状态，**没有多个 LLM 节点**。原文保存在材料服务，不进入这份 DSL 的输入与输出；模型实际在材料 worker 中执行。

## 下一阶段的多模型分工

| 阶段 | 建议实现位置 | 交付与判断 |
|---|---|---|
| 接收与授权 | 业务服务 | 编码、输入边界、来源台账、SHA256、版本、幂等 |
| 上下文组织 | 材料服务 | 已知回复关系与事件窗口；原文不改写，脱敏记录映射 |
| 候选筛选 | 轻量模型 / 规则服务 | 路由建议与标签候选；保留中性、投诉、求助和引用样本进入抽查 |
| 主研判 | 中文大模型服务 | 按 schema 提取行为、对象、逐字引语、缺失信息 |
| 独立复评 | 不同模型系列或独立微调模型 | 独立读取原文，先形成观察，再与主模型结果比较 |
| 确定性校验 | 业务服务 | 实际模型身份、tokens、终止原因、JSON、消息ID、引用一致性 |
| 分歧处理 | 规则 + 大模型辅助 | 记录分歧和各模型引用；关键分歧交人工，不能多数投票判违法 |
| 人工复核 | 工作台 | 有权限的复核员补充语境、确认/驳回、留理由与修订历史 |
| 数据回流 | 受控标注平台 | 经授权与仲裁的训练数据；不直接将业务意见当金标 |

避免让复评模型先读主模型结论而受到诱导。优先使用不同模型系列；同一基座换三个提示的结果通常有相关错误，不能称为三个独立证据。

Dify 负责步骤编排、路由和状态，材料/模型服务负责原文与严格输出；密钥不写进 DSL。升级用新的 workflow 和 pipeline 版本，原版工作流继续支持历史任务。涉及原文的节点若必须进入 Dify，应先明确该部署的访问权限、日志留存和数据出域范围。

## 效率策略

先测量按文长/事件类型分组的 P50/P95 时延、tokens、GPU显存峰值与队列等待，再决定并发和大小模型路由。重复材料按哈希与版本复用可审计的处理结果；幂等键避免重复投递，但不能在版本改变后沿用过时结论。

当前实现是一个 worker、一个网关推理并发。后续使用专用队列与多 GPU worker，任务租约、限流、重试和幂等仍由服务端负责。不要通过增加 Uvicorn workers 扩容当前 SQLite 版本。

轻量筛选应留随机阴性抽查和困难负例复评，以测量漏检；阈值必须在开发集确定。跨域数据、未知作者、缺上下文、模型分歧、引用异常与置信度不足进入人工队列。模型自己生成的 confidence 不是校准概率。

## 正确率与司法相关误判

评测至少分开报告攻击标签的 precision/recall/F1、正常批评/消费投诉/引语求助的误报率、证据跨度匹配、对象归属错误、上下文不足识别与有效覆盖率。按来源平台、时间、方言、隐喻/谐音、多人对话分别检查，报告样本量与置信区间。

结果应允许拒绝下结论。输出校验失败不能计为正确阴性；人工转交比例、超时率和拒收率同样列入报告。分歧高、语境缺失或相关群体误报明显时，回到标注准则与样本检查，而非仅提高模型规模。

## 来源与追踪体系

下一阶段增设来源登记：发布平台/导出系统、原始URL或受控记录ID、获取时间、获取依据、授权文件、原始哈希、脱敏版本、关系验证状态、保留期限。关系图谱仅以有证据支持的 reply/repost/同事件链接建立；相似昵称、文本或 IP 不能单独证明同一主体或组织行为。

生产证据保全应接单位认可的签名、时间戳、对象存储与外部审计。原始哈希证明特定版本内容的一致性，不证明内容真实、发布人真实身份或取得程序合法。

## 生产建设条件

身份与组织隔离、存储加密/备份、权限回归、模型服务隔离、监控与告警、滚动发布、灾备、数据权利处置和独立金标盲测应共同完成。当前源码没有宣称具备这些完整能力；[路线图](ROADMAP.md) 给出阶段验收。
