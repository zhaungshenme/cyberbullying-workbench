# 持续更新路线图

项目后续将持续更新。以下按可验收交付物组织，不承诺未经确认的日程、准确率或已存在的算力。

| 阶段 | 交付 | 验收条件 |
|---|---|---|
| 已实现：工程原型 | 多角色工作台、导入、上下文、Dify 引用任务、固定模型网关、校验、复核、报告、分页 | 源码与自动测试可运行；入库与推理状态区分 |
| 下一步：服务器模型适配 | 固定 revision 的 vLLM 适配层、模型登记、预算与结构生成、实际 usage 与错误状态 | 新旧接口契约、引用/截断/身份/预算拒收测试与真实 GPU 链路 |
| 数据治理 | 来源台账、许可核验、事件/时间分组切分、双人标注与仲裁、盲测库 | 每条训练/测试样本可追溯；无事件泄漏；授权可核验 |
| 多模型协作 | 筛选、主研判、独立复评、分歧转人工的 Dify 新版本 | 对比单模型误报/漏报与延迟；相关错误与异常计入评测 |
| 领域微调 | 基线、SFT/LoRA/QLoRA 实验、模型卡、数据与训练版本 | 独立冻结测试、困难负例与群体误报评估、可复现实验 |
| 溯源追踪 | 合法来源导入、消息传播关系、时间线、版本与保全记录 | 关系有明确依据，身份未知可表达，完整取证流程另验收 |
| 生产可靠性 | 数据库/队列迁移、单位身份接入、隔离、外部审计、压测、备份恢复 | 不丢历史、不越权、容量与恢复目标达到业务验收 |

每次模型、提示、标签、工作流或窗口策略变更都记录版本，保留原结果。重要更新附迁移步骤、回滚条件、测试报告与尚未解决的问题。

反馈请使用 GitHub Issues。数据贡献先提供来源与授权描述；公开 Issue 和 Pull Request 不上传原始敏感材料、账号令牌、案件文件或未经授权的社交文本。
